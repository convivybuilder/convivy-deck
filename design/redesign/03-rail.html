What changed from today

  • 216pt, 26pt rows, 13pt names. Up from 200 and 6pt vertical padding. The extra width goes to the trailing column so a count and chevron never crowd a long name (Vivy Commercial is the longest real one).
  • Children hang on a spine. The 1pt rule the cockpit uses for an expanded epic, drawn from the parent's mark column down to the last child, with a 7pt tick into each child. At 44pt the spine goes and the tick stays, indented 10pt, so a child is still a child when the names are gone.
  • OTHER SESSIONS and START are the same section label as BEAD: 10pt, tracked, --ink-2. At 44pt they are 1pt rules, and the rows under them are hover-only for a name; the List's own arrow keys still reach them, and Cmd-1…9 reaches the top-level crews as it does today.
  • A START row is a hollow square at full ink. Today it is a play glyph in the crew's hue; the first draft dimmed it, which made it the same 30% square as a stopped crew. Hollow says "not yet" where dimmed says "was".
  • A terminal-only row previews the hue it would take. themeForSession already hashes a bare name to a theme, so the hue exists before adoption; Car and Tennis draw it at the stopped row's 30%, so it reads "would be" rather than "is".
  • "+ New" stays, for now. The operator's 2026-09-03 call makes the steward's new-crew skill the only creation path and deletes Deck's button, but the issue recording it (issue_01M1MW2E4G5SJPWNCMNH0KCJES) is open and its thread gates the deletion on a session-agent crews verb that does not exist. Until Deck reads crews.d/, a user with no steward has no other path, so the foot keeps the button and RailRow.onNewSession keeps its context-menu item. When the reader lands, both go and the bead pane becomes the foot. The first draft removed them early and was wrong to.
  • The bead pane's second fact is relative. "reordered 4d ago" (the Course's last reordered event, 2026-08-31) says whether the plan moved since you looked, which the fraction cannot; a bare "v8" said nothing a reader could use.
