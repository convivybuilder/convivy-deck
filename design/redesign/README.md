# The Deck visual spec

**These pages are the specification, not a suggestion.** The operator approved them on
2026-09-04 as the visual target for Deck's UI: *"Use this as the visual spec,
we don't need agents or you to override things that you would do differently.
If you do ID any issues, bring them to me instead of overriding."*

That instruction binds every agent that builds against this. **If something
here looks wrong, cannot be built as drawn, or contradicts a decision recorded
elsewhere in the codebase, raise it with the operator and stop — do not substitute your
own judgement and do not quietly build something else.** A mismatch between
what shipped and what these pages draw is a defect in the ship, not a licence
to redesign.

regenerate** — editing the HTML directly is how the pages and the generator
drift apart.

## Where the colours come from

`build.py` ports `OKLCH.swift` and `ThemeRecipe.solveLightness` rather than
copying their constants. Every ink is a start point plus a contrast target
(text 4.5, marks 3.0, hairlines 1.6/1.3), solved per appearance and per
selected-crew hue for all ten catalog hues, with each crew's mark solved twice
— on the rail surface and again on the selection wash, the way
`RailRow.markBacking` does. The build prints the measured ratios and writes
them into `index.html`. **All 80 pairs pass their targets.** A change that
breaks one is a regression the build will show you.

## The right column's identity (B2)

The operator approved Option B2 on 2026-10-04 (`issue_01M447Y6GWYGJW2Z0QKFCFTVBQ`).
Every right-column tab opens with a band: an icon, a title, a place line and
the tab's own controls. The band's surface and its rule carry the tab's
identity, and the rule is the 2pt rule under the band.

| Tab | Band | Icon | Rule | Place line |
|---|---|---|---|---|
| Cockpit (also Board, Crew) | window chrome | `square.grid.2x2.fill` | plain separator | the project |
| Shell | the selected crew's band | `terminal.fill` | the crew's ink, 2pt | `user@host` |
| Local | graphite band | `laptopcomputer` | graphite ink, 2pt | "this Mac" |
| Slate | the crew band of the session the sheet was opened for | `list.bullet.clipboard.fill` | the crew's ink, 2pt | "crew on host" |

**The rule.** A crew's colour marks a surface that talks to a crew's host.
Graphite marks the laptop. A surface that does neither stays neutral.

**Where the colours come from.** `build.py` derives each band from the same
recipe as the app: the band is the session pane's frame tint (the canvas mixed
halfway to the extreme), the rule and icon are the crew's accent solved to 3:1
on that band (`ThemeRecipe.dotInk`), and each place line is the neutral solved
to 4.5:1 on its own band (`ThemeRecipe.placeLineInk`). Graphite is the recipe
at zero chroma, and it is not one of the ten hashed crew themes, so no crew
reads as the laptop.

**What the pages do not draw.** The Local Terminal rail row no longer exists,
so there is no rail glyph for the laptop. The fifth-segment panes (Item,
Viewer, Editor, Run) keep their own headers, so the band's shape changes when
one of them opens. CSS truncates the place line at its end; the app truncates
it in the middle and keeps the full text in a tooltip.

## Decisions the operator made on the spec

Both questions the spec raised are answered. They are drawn as the target, and
**neither is built yet** — each belongs to a work item under the epic.

- **⌘1–9 selects a permission-prompt option** (the operator, 2026-09-05: "sure
  why not, seems good"). Today `OptionCard` is a plain `Button` with no
  `.keyboardShortcut`, so answering a prompt is mouse-only, and the number on
  the card is drawn only because the number is what Deck sends.
- **"Raw terminal" becomes "Terminal View"** everywhere (the operator, 2026-09-05). The
  toolbar toggle already reads Terminal View; the toggle's tooltip and the
  header on the terminal pane itself still say "Raw terminal" in the shipping
  app. The way back stays "Session View".

## Where these pages still disagree with the app, the app wins

**The epic shipped on 2026-09-05 and these pages were not fully reconciled
against it.** A systematic pass during PR #188 walked every rule in the
`.crow`, `.epic` and cockpit-index blocks against the Swift it depicts, and
found a set of disagreements beyond the three that PR corrected. The operator
ruled on 2026-09-05 that the app-side of that list gets fixed and **the remainder
is superseded rather than chased**: where one of these pages contradicts the
shipping code below, treat the code as authoritative and do not "correct"
working code back to the mockup.

- **`.crow .g.held` / `.g.attn`** draw on `--attn-mark`. The code uses
  `attentionTextInk` (text contrast, `--attn-text`), and `ThemeRecipe`
  documents that as deliberate — the held pause icon is named there as one of
  the badges held to text contrast rather than mark contrast.
- **`.crow .m .held`** colours the whole "pause 2" span in the attention ink.
  The app colours only the icon; the count draws in the secondary ink.
- **`.epic .cap b`** draws the "Done when:" label in full-strength `--ink`.
  The app builds it as a semibold run inside one concatenated `Text`, so it
  inherits the sentence's secondary ink — heavier, not brighter.
- **`.epic .loading`** is 11px; the code's loading line is `frameFont(.caption)`
  = 10pt.
- **The `.epic` empty state** has no rule of its own and falls through to the
  generic `.panel .empty` at 11.5px, a pre-typography-rework leftover; the code
  draws `frameFont(.caption)` = 10pt.
- **`.cockpit .index a` and its `.n`** are 11px; the code's index row is
  `frameFont(.label)` = 10pt.
- **`01-window.html:1297`** moves the subscription into the model token's
  tooltip rather than its own badge. The code draws it as its own token again
  (issue_01M1Y7A36AZ42VSK3QYZBYSNQD, 2026-09-07): which credential a session
  spends is the one vital that costs money when misread, and a tooltip is not
  glanceable — a session left on the wrong subscription overnight cost $50
  before anyone noticed.

**The app-side items from the same pass were fixed rather than recorded** —
the "more" link's colour, the chevron's ink tier, and the index count's weight.
Those were cases where the mockup was right and the code was not.

## How this was produced

A designer drafted it, an adversarial critic reviewed it against the running
code, and the designer revised. The critic's most useful catch: the proposed
"aesthetic risk" of a serif transcript **already ships** in
`agent-platform/lib/agent-platform/session_view.py`, so the redesign was
arguing for a decision already taken. Several other claims about today's UI
were verified against the source rather than accepted.

Two of the critic's findings were pushed back on rather than adopted, and both
are recorded in `index.html`: the ribbon and the cockpit do not disagree about
data (a `claimed` epic that is not `currentId` correctly draws *ahead* at
ribbon zoom and *in progress* in the panel), and `+ New` stays until the
`session-agent crews` verb lands, because removing it now leaves a user with no
steward and no way to create anything.
